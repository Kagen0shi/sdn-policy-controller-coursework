# SDN Policy Controller Coursework

## Опис проєкту

Цей репозиторій містить програмну реалізацію практичної частини курсової роботи на тему:

**«Впровадження Software Defined Networking для гнучкого управління маршрутами і доступом абонентів»**

Проєкт реалізує Python-модель SDN-контролера, який виконує централізоване керування маршрутами, перевірку політик доступу абонентів та генерацію OpenFlow-подібних правил для комутаторів. Модель використовується для дослідження переваг програмно-керованих мереж порівняно з традиційною статичною маршрутизацією.

## Мета проєкту

Метою програмної реалізації є моделювання роботи SDN-контролера, який:

* має глобальне уявлення про топологію мережі;
* перевіряє права доступу абонентів відповідно до їхніх ролей;
* будує маршрути між абонентами та сервісами;
* блокує несанкціоновані запити;
* перебудовує маршрути після відмови каналу;
* формує OpenFlow-подібні правила для мережевих комутаторів;
* порівнює ефективність SDN-підходу зі статичною маршрутизацією.

## Основна ідея

У традиційній мережі правила маршрутизації та доступу часто налаштовуються окремо на кожному мережевому пристрої. Це ускладнює масштабування, зміну політик доступу та швидке відновлення після відмов.

У моделі Software Defined Networking логіка керування переноситься до централізованого контролера. Завдяки цьому контролер може аналізувати стан усієї мережі, приймати рішення щодо маршрутів і доступу абонентів, а також автоматично створювати правила для комутаторів.

## Реалізовані можливості

У проєкті реалізовано:

* графову модель SDN-мережі;
* абонентів із різними ролями;
* сервіси з різними рівнями доступу;
* механізм перевірки політик доступу;
* побудову маршрутів у мережі;
* моделювання відмов каналів;
* перебудову маршрутів після аварій;
* генерацію OpenFlow-подібних flow rules;
* порівняння кількох підходів до керування мережею;
* збереження результатів у CSV;
* побудову графіків для аналізу.

## Ролі абонентів

У моделі використовуються такі типи абонентів:

| Роль    | Приклад доступу                                 |
| ------- | ----------------------------------------------- |
| guest   | доступ лише до гостьового інтернету             |
| student | доступ до LMS, відеосервісів та інтернету       |
| teacher | доступ до LMS, файлових ресурсів, відеосервісів |
| admin   | доступ до всіх сервісів                         |
| blocked | доступ заборонено                               |

## Алгоритми, що порівнюються

У програмній моделі порівнюються три підходи.

### Static Routing

Базовий підхід, який імітує традиційну статичну маршрутизацію. Маршрути задаються наперед і не завжди можуть бути швидко адаптовані після зміни стану мережі.

### SDN Shortest Path

SDN-контролер будує маршрут на основі поточної графової топології мережі та вибирає найкоротший доступний шлях.

### Policy-Based SDN Controller

Основний алгоритм роботи. Контролер спочатку перевіряє роль абонента та політику доступу до сервісу. Якщо доступ дозволений, система будує маршрут і генерує OpenFlow-подібні правила для комутаторів. Якщо доступ заборонений, запит блокується.

## Сценарії дослідження

У роботі використано кілька сценаріїв:

1. **normal_operation** — звичайна робота мережі;
2. **unauthorized_access** — спроби доступу до заборонених сервісів;
3. **link_failure** — відмова одного або кількох каналів;
4. **role_change** — зміна ролей абонентів;
5. **mass_requests** — масова генерація запитів до сервісів.

## Метрики оцінювання

Для аналізу результатів використовуються такі показники:

* частка дозволених потоків;
* частка заблокованих потоків;
* кількість порушень політик доступу;
* середня довжина маршруту;
* кількість потоків, перебудованих після відмови;
* кількість недоступних потоків;
* кількість згенерованих flow rules;
* успішність відновлення маршрутів після аварії.

## Опис основних модулів

### main.py

Головний файл запуску проєкту. Запускає експерименти, зберігає результати та будує графіки.

### config.py

Містить основні параметри моделі: ролі абонентів, сервіси, сценарії та налаштування експериментів.

### models.py

Описує основні сутності системи: абонентів, сервіси, комутатори, запити, маршрути, політики доступу та flow rules.

### topology.py

Створює графову модель SDN-мережі.

### policy_engine.py

Відповідає за перевірку політик доступу. Визначає, чи має певний абонент право звертатися до конкретного сервісу.

### routing_engine.py

Будує маршрути в мережі та виконує перебудову маршрутів після відмов каналів.

### controller.py

Моделює роботу SDN-контролера. Об’єднує перевірку доступу, маршрутизацію та генерацію правил.

### traffic_generator.py

Генерує запити абонентів до сервісів у різних сценаріях.

### experiments.py

Запускає експериментальні сценарії та порівнює алгоритми.

### metrics.py

Розраховує показники ефективності.

### visualization.py

Будує графіки та схему SDN-топології.

## Встановлення залежностей

Рекомендовано використовувати віртуальне середовище Python.

```bash
python -m venv .venv
```

Активація середовища у Windows PowerShell:

```bash
.\.venv\Scripts\Activate.ps1
```

Встановлення бібліотек:

```bash
pip install -r requirements.txt
```

## Запуск проєкту

Для запуску моделі потрібно виконати:

```bash
python main.py
```

Після запуску програма створить або оновить файли в папці `results/`.

## Результати

У папці `results/` зберігаються:

* зведені таблиці результатів;
* рішення контролера щодо потоків;
* згенеровані OpenFlow-подібні правила;
* графіки для аналізу;
* схема SDN-топології.

Основний результат дослідження полягає в тому, що Policy-Based SDN Controller забезпечує централізоване керування доступом, блокує несанкціоновані запити, перебудовує маршрути після відмов каналів і формує правила для комутаторів без ручного налаштування кожного пристрою.

## Практичне значення

Розроблена модель демонструє, як SDN-підхід може використовуватися для гнучкого управління мережею з великою кількістю абонентів. Такий підхід дозволяє швидко змінювати правила доступу, централізовано контролювати маршрути та підвищувати керованість мережевої інфраструктури.
